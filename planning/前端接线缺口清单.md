# Ordo 前端接线缺口清单

> 最近核对：2026-09-03，基于当前工作区 `web/app.js`、`server/src/` 与 `Ordo计划纠正.md` 的静态审查。
> 用途：这是前端未修复、未完成和未验收事项的唯一持续清单。
> 口径：API 方法存在不等于页面接线完成；只有真实读取、正确传参、消费响应、处理失败，并以服务端确认更新界面，才算完成。

## 一、维护规则

1. 主清单只保留当前未完成、未修复或未验收的前端任务。
2. 新发现的前端问题必须补充到本文件，注明优先级、页面、问题、依赖和验收条件。
3. 已完成任务从主清单移除，只在“完成记录”中保留一句摘要；不要让过期任务继续影响施工判断。
4. API 已定义但页面未调用、参数不对、响应未渲染、操作后未刷新，均视为未完成。
5. 已连接状态展示演示数组、固定统计或伪造状态，均视为缺陷；真实空数据必须显示空状态。
6. 未连接时允许保留演示模式，但所有相关页面必须明确标注“演示模式 · 数据非真实”。
7. 点击后立即 toast、仅修改本地 state、使用 `setTimeout` 模拟完成，不能作为真实成功。
8. 行号只用于定位本次核对时的代码；修改代码后以函数名、页面名和最新搜索结果为准。

## 七、后端契约速查

- **chunks**：`id, chunk_logical_id, content_md, content_text, type, token_count, revision_number, excluded, warnings, artifact_id, document_id, document_title, embedding_model, confidence, generated_by, created_at`
- **releases**：`id, version, status, manifest.chunkCount, manifest.contentHash, quality.valid, content_hash, created_at, activated_at`
- **documents**：`id, title, status, media_type, revision_number, size_bytes, parser_id, warnings, artifact_id, quality_status, chunk_count, updated_at`
- **tasks**：`id, type, status, progress, input, result, error_code, error_message, attempt, created_at, finished_at`
- **document.parse result**：`artifactId, documentId, revisionId, qualityStatus, blockCount, warnings`
- **release.build result**：`releaseId, version, status, chunkCount, quality`
- **traces**：`id, conversation_id, release_id, query, status, evidence_status, stages, metrics, created_at`
- **trace stage**：`name, status, durationMs, output`
- **openCitation**：`id, title, locator, excerpt, documentStatus, contentMd, contentText, locationLabel`
- **settings**：`general, query, ingestion, backup`；每组带 `updatedAt`
- **backups**：`id, status, storage_key, manifest, checksum, created_at`
- **health**：`status, checkedAt, components`
- **diagnostics**：`generatedAt, appVersion, schemaVersion, deploymentProfile, platform, health, dashboard, audit, capabilities`
- **version**：`appVersion, schemaVersion, deploymentProfile, platform, node`
- **search**：`query, results[{type,id,title,subtitle,route}], total`
- **conversations**：列表含 `knowledge_base_name, dataset_name, release_version, message_count`；详情含 `messages[]`
- **widget clients**：列表只返回 `secret_mask`；create 的 `clientSecret` 只返回一次

后端会把数据库的 `*_json` 字段转换为解析后的无后缀副本，例如 `stages_json -> stages`、`result_json -> result`、`locator_json -> locator`。前端优先消费解析后的字段。

## 八、统一验收红线

1. 任何成功提示必须基于非空且字段有效的后端响应。
2. 进度、状态和耗时只来自真实任务或 Trace，不伪造。
3. 秘密只显示掩码；旧值永不回显；一次性 secret 不进入长期前端状态。
4. 未连接可以保留明确标识的演示模式；已连接禁止展示假数据。
5. 一个会话固定一个知识库和 Release；切换知识库创建新会话。
6. Release 不可变；发布、激活和回滚只创建版本或切换指针，不覆盖历史。
7. Citation 必须使用真实 ID，并由后端验证 chunk revision、Release 和来源链。
8. 未启用能力必须显示“未启用/暂不支持”及原因，不伪造可用结果。
9. HTML/HTM 继续由前后端拒绝；文件选择器不包含这些格式。
10. 错误、空数据、断网、权限和任务失败都必须有独立状态，不得回退成成功或演示内容。

## 九、验证清单

每完成一批任务后执行：

1. `node --check web/app.js`
2. `npm --prefix web test`
3. 涉及后端契约时运行 `npm --prefix server test`
4. 涉及完整链路时运行 `server/scripts/fullchain-smoke.mjs`，R1 无关问题拒答仍按已知问题单独记录
5. 使用浏览器逐页检查桌面和移动视口，以及加载、空数据、错误、断网和权限状态
6. 将已完成项移出本清单主任务区，并在下方增加简短完成记录
7. 每批独立提交；不把 `.ordo-data/`、秘密、日志或浏览器调试产物加入 Git
