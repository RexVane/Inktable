# Ordo 前端接线缺口清单

> 最近核对：2026-09-03，基于当前工作区 `web/app.js`、`server/src/` 与 `Ordo计划纠正.md` 的静态审查。
> 用途：这是前端未修复、未完成和未验收事项的唯一持续清单。
> 口径：API 方法存在不等于页面接线完成；只有真实读取、正确传参、消费响应、处理失败，并以服务端确认更新界面，才算完成。

## 一、维护规则

1. 主清单只保留当前未完成、未修复或未验收的前端任务。
2. 新发现的前端问题必须补充到本文件，注明优先级、页面、问题、依赖和验收条件。
3. 已完成任务从主清单移除，只在“完成记录”中保留一句摘要；不要让过期任务继续影响施工判断。
4. API 已定义但页面未调用、参数不对、响应未渲染、操作后未刷新，均视为未完成。
5. 已连接状态展示演示数组、固定统计或伪造状态，均视为缺陷；真实空数据必须显示空状态。
6. 未连接时允许保留演示模式，但所有相关页面必须明确标注“演示模式 · 数据非真实”。
7. 点击后立即 toast、仅修改本地 state、使用 `setTimeout` 模拟完成，不能作为真实成功。
8. 行号只用于定位本次核对时的代码；修改代码后以函数名、页面名和最新搜索结果为准。

## 二、当前状态

| 状态 | 页面/模块 |
|---|---|
| 基本就绪 | 首页、新对话弹窗、文件上传与任务等待 |

当前 API 客户端和服务端主要路由已经基本齐全。后续工作的重点不再是批量补 API 方法，而是页面真实渲染、参数和响应契约、任务状态消费、错误/空状态以及后端确认后的刷新。

## 四、P1：核心工作台真实化

### P1-01 数据集页

- 真实渲染数据集、文档、Release、chunks 计数和选中项，不以 demo 数组填充真实空结果。
- 搜索框、筛选器、目录树和 Inspector 使用真实数据并产生实际过滤行为。
- 分页使用真实 limit/offset；后端未提供 total 时不得显示伪造总页数，应采用“上一页/下一页”或诚实的有限结果提示。
- 批量删除必须调用真实后端接口；完成后重新拉取列表。
- Wiki、Graph、权限等暂未启用 tab 显示不可用原因。

### P1-02 数据登记页

- 修正 `getDocuments()` 数组响应的消费，不再只读取 `docRes.items`。
- 让真实知识库、文档、来源和任务数据实际参与模板渲染；当前读取变量不得闲置。
- 来源树、来源表、最近导入、待处理项、筛选和分页不再使用固定 8 行样例。
- directory preview 必须展示 `candidates[]` 供确认；确认后调用 import，并轮询 archive/directory task 到终态。
- 网盘、数据库和本机探测等未启用能力显示诚实禁用态。

### P1-03 数据解析页

- 任务队列、状态、progress、错误信息、attempt、warnings 和质量状态全部使用真实任务/文档数据。
- 原文预览通过文档 `artifact_id` 获取真实 Markdown；不存在 Artifact 时显示明确空态。
- 移除固定 `p1-p5`、`10,852`、静态页码、资源监控和质量百分比，或仅放入明确离线演示分支。
- 重试必须使用真实任务 ID；后端没有 pause/resume 接口时，开始/暂停按钮应禁用并标“暂未接入”，不能只改本地 state 后报成功。

### P1-04 构建知识索引页

- 真实渲染 chunks、修订号、excluded、warnings、document title、token count 和选中块正文。
- 编辑、拆分、合并、禁用、恢复后以服务端响应刷新列表；409 `CHUNK_REVISION_CONFLICT` 提示重新加载最新修订。
- 构建 Release 后等待真实 task 终态，展示真实 release ID、version、chunkCount、quality 和错误。
- 激活/回滚只表现为不可变 Release 的活动指针切换；单版本回滚 409 显示为不可执行条件。
- 查询验证使用活动 Release ID，渲染真实命中、分数和 locator，并标明“仅验证检索”。
- 质量门、一致性视图和指标不得使用固定成功状态。

### P1-05 问答流程 8 页

- Trace 选择器和标题栏已接真实数据，剩余工作是将 8 页正文全部映射到 `trace.stages[]` 的真实 `status`、`durationMs` 和 `output`。
- 问题解析、向量化、路由、召回、融合、重排、Prompt 和回答页面不得继续显示固定问题、固定候选或固定耗时。
- 前端 embedding 维度使用后端实际返回值；当前本地 query embedding 为 128 维时不得显示固定 1536。
- 无 Trace 时显示“暂无真实 Trace，请先完成一次问答”，不得创建 `QA-DEMO-001`。
- 后端没有阶段重放、重新向量化或模板保存端点时，相关按钮显示“暂未接入”，不得 `setTimeout` 模拟成功。

### P1-06 智能问答会话边界

- 历史列表和消息回放只使用真实 conversations/messages；离线演示记录不得混入在线列表。
- 新对话选择的知识库必须传入实际会话创建；切换知识库必须创建新会话。
- 页面显示真实 knowledge base、dataset 和固定 release/version，不再显示静态知识库或固定 `v7`。
- “查看问答流程”携带当前 `state.lastTrace.id` 并在 QA 页面选中对应 Trace。

## 五、P2：设置、助手和管理功能完整化

### P2-01 通用设置

- 当前 checkbox 的 `data-key`、GET settings 和 PUT general 基础已存在，旧的“完全无法保存”任务已移除。
- 剩余：语言、工作空间、下载目录、清理策略、日志级别等字段纳入真实读取和保存。
- “取消”恢复服务端已保存值；“恢复默认”必须有明确默认值并写回服务端，不能只 toast。
- 页面级 toggle 不得只写 localStorage 后冒充服务端设置已保存。

### P2-02 模型设置

- 完成真实模型列表、基础配置、凭据、速率限制、测试和用量 5 个 tab。
- 默认模型分配、能力、状态和用量没有后端数据时显示“暂未接入”。
- 重新授权调用真实 PATCH，旧 Key 永不回显，成功后只刷新掩码。

### P2-03 智能助手

- 当前列表、创建、更新、发布和暂停已有部分真实接线；旧的“列表完全没用 state.assistants”任务已移除。
- 在线空列表显示空状态，不回退演示助手。
- 创建助手使用真实 dataset/knowledge base，并展示是否存在可用活动 Release。
- “发布新版本”必须调用后端并以返回结果更新版本；无对应能力时显示“暂未接入”，不得本地递增。
- Widget client 创建、轮换、撤销、一次性 `clientSecret` 和后续 `secret_mask` 尚未完成；未实现前不得生成假凭据或安装代码。

### P2-04 存储设置

- 渲染真实备份列表，包括状态、创建时间、文件数、大小和校验信息。
- 增加恢复入口和确认说明；恢复写入隔离目录，不覆盖当前实例；展示真实任务结果。
- 一致性检查和诊断导出使用 `/diagnostics`，展示 audit.verify 和 health components 的真实结果。
- 7 个 tab 必须有对应内容；PostgreSQL、MinIO、Vault、Redis、容量趋势和覆盖度没有真实数据时显示“未启用/暂未接入”。

### P2-05 版本设置

- appVersion、schemaVersion、deploymentProfile、platform 和 node 使用 `/version` 返回值。
- 健康状态和诊断包使用 `/health`、`/diagnostics`，诊断导出按钮绑定真实 handler。
- 删除固定构建号、固定 API 版本、固定组件健康、固定版本历史和固定发行说明；没有数据源时显示“暂未接入”。
- 本地版本没有更新通道时明确显示“无更新通道”，不得使用 `setTimeout` 宣称“当前已是最新”。

### P2-06 删除流程与 Feature Flags

- 为数据集删除、会话删除和批量文档删除补齐真实入口、影响确认、后端调用和列表刷新。
- Feature Flags 页面需要调用 `getFeatureFlags()`，展示真实 0/1 或 boolean 状态，并以明确 boolean 提交 `putFeatureFlag()`。
- 字符串 `"false"` 不得通过 `Boolean(value)` 误转为 true。
- 删除失败或 409 影响约束必须展示服务端原因，不得先从本地列表移除。

## 七、后端契约速查

- **chunks**：`id, chunk_logical_id, content_md, content_text, type, token_count, revision_number, excluded, warnings, artifact_id, document_id, document_title, embedding_model, confidence, generated_by, created_at`
- **releases**：`id, version, status, manifest.chunkCount, manifest.contentHash, quality.valid, content_hash, created_at, activated_at`
- **documents**：`id, title, status, media_type, revision_number, size_bytes, parser_id, warnings, artifact_id, quality_status, chunk_count, updated_at`
- **tasks**：`id, type, status, progress, input, result, error_code, error_message, attempt, created_at, finished_at`
- **document.parse result**：`artifactId, documentId, revisionId, qualityStatus, blockCount, warnings`
- **release.build result**：`releaseId, version, status, chunkCount, quality`
- **traces**：`id, conversation_id, release_id, query, status, evidence_status, stages, metrics, created_at`
- **trace stage**：`name, status, durationMs, output`
- **openCitation**：`id, title, locator, excerpt, documentStatus, contentMd, contentText, locationLabel`
- **settings**：`general, query, ingestion, backup`；每组带 `updatedAt`
- **backups**：`id, status, storage_key, manifest, checksum, created_at`
- **health**：`status, checkedAt, components`
- **diagnostics**：`generatedAt, appVersion, schemaVersion, deploymentProfile, platform, health, dashboard, audit, capabilities`
- **version**：`appVersion, schemaVersion, deploymentProfile, platform, node`
- **search**：`query, results[{type,id,title,subtitle,route}], total`
- **conversations**：列表含 `knowledge_base_name, dataset_name, release_version, message_count`；详情含 `messages[]`
- **widget clients**：列表只返回 `secret_mask`；create 的 `clientSecret` 只返回一次

后端会把数据库的 `*_json` 字段转换为解析后的无后缀副本，例如 `stages_json -> stages`、`result_json -> result`、`locator_json -> locator`。前端优先消费解析后的字段。

## 八、统一验收红线

1. 任何成功提示必须基于非空且字段有效的后端响应。
2. 进度、状态和耗时只来自真实任务或 Trace，不伪造。
3. 秘密只显示掩码；旧值永不回显；一次性 secret 不进入长期前端状态。
4. 未连接可以保留明确标识的演示模式；已连接禁止展示假数据。
5. 一个会话固定一个知识库和 Release；切换知识库创建新会话。
6. Release 不可变；发布、激活和回滚只创建版本或切换指针，不覆盖历史。
7. Citation 必须使用真实 ID，并由后端验证 chunk revision、Release 和来源链。
8. 未启用能力必须显示“未启用/暂不支持”及原因，不伪造可用结果。
9. HTML/HTM 继续由前后端拒绝；文件选择器不包含这些格式。
10. 错误、空数据、断网、权限和任务失败都必须有独立状态，不得回退成成功或演示内容。

## 十一、计划外但仍需决策的后端问题

- **R1**：`local-hash-v1` 可能让无关问题获得超过当前阈值的向量分，导致严格证据模式下未稳定拒答。该项影响前端 evidence status 的可信度，但属于后端检索策略决策，不在本前端清单内直接修改。
- 子 Trace 重放、SSE 流式回答、高级 PDF/OCR/VLM、Golden 评测、企业权限、来源类型独立标记、Embedding 能力探测等仍属于计划差距；前端在后端能力落地前统一显示“暂未接入”。
