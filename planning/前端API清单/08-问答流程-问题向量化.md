## 二、本页面全部 API 契约总览表 (共 8 个 API)

| 序号 | 请求方式 | 接口路径 | 对应前端组件 / 触发时机 | 核心功能说明 |
|:---:|:---:|---|---|---|
| **1** | `GET` | `/api/v1/traces/:traceId/stages/embed` | 页面初次加载 / 切换至此步 | **主数据源**：一次性拉取 4 大指标、查询文本、DAG 状态、向量生成详情、前 10 维切片与散点图数据 |
| **2** | `GET` | `/api/v1/traces/:traceId/pipeline` | 顶部 8 阶段步进指示条 | 获取 8 阶段执行状态（`completed`）与各阶段耗时 |
| **3** | `POST` | `/api/v1/traces/:traceId/stages/embed/recompute` | 底部 `[ ⟳ 重新向量化 ]` 按钮 | 强制绕过缓存，使用当前配置模型重新跑一次向量化推理并就地刷新页面 |
| **4** | `GET` | `/api/v1/traces/:traceId/stages/embed/scatter` | 散点图右上角 `相似度阈值 >= 0.40 ∨` 下拉 | 动态切换相似度阈值（0.3/0.4/0.5/0.6），按阈值重新过滤高亮散点并重算命中数与最高相似度 |
| **5** | `POST` | `/api/v1/traces/:traceId/stages/embed/compare-models` | 底部 `[ 📊 对比模型 ]` 按钮 | **模型横向评测**：唤起对比弹窗，同时测试 bge-large、text-embedding-3-small、Ollama 本地模型的生成耗时与散点聚集度 |
| **6** | `POST` | `/api/v1/traces/:traceId/replay` | 底部 `[ ▶ 从此阶段重跑 ]` 绿色主按钮 | **核心调试闭环**：以此向量化结果为起点，级联重放 3~8 阶段并生成新衍生 Trace |
| **7** | `GET` | `/api/v1/traces/:traceId/stages/embed/vector` | 右侧向量预览 `[ 📋 复制 ]` / 导出 | 获取完整的 1536 维全量浮点数数组（支持 JSON 或 CSV 复制下载） |
| **8** | `GET` | `/api/v1/traces/:traceId/stages/embed/logs` | 开发者调试 / 日志查看 | 获取底层 Tokenizer 分词流水、Embedding API 网络耗时与推理日志 |

### 2. 重新向量化 (POST /api/v1/traces/:traceId/stages/embed/recompute)
* **请求方法**：`POST`
* **请求体**：
```json
{
  "forceRefresh": true,
  "overrideModel": null
}
```
* **响应载荷 (200 OK)**：返回重新生成的全量向量生成详情与全新耗时，Toast 提示：`"✓ 向量模型重新推理完成，耗时 38ms"`。

### 3. 动态切换散点阈值 (GET /api/v1/traces/:traceId/stages/embed/scatter)
* **请求方法**：`GET`
* **Query 参数**：`?threshold=0.50`
* **响应载荷 (200 OK)**：
```json
{
  "code": 0,
  "data": {
    "threshold": 0.50,
    "hitChunksCount": 18,
    "maxSimilarity": 0.8621,
    "points": [ ... ]
  }
}
```
散点图根据返回的新点集，实时平滑更新圈内绿色高亮点的分布与数量（32 ➔ 18）。

## 五、端到端全业务闭环与调试场景

### 场景：知识库检索“冷门提问”向量偏离排查与模型对比
1. **现象**：用户问了一个行业专业术语问题，发现最终模型给出的答案不够贴切；
