# 07-问答流程-问题解析 前端 API 清单与三大组件交互契约

> **文档定位**：对应原型设计稿 [`07-问答流程-问题解析.png`](file:///d:/AIApp/Ordo/planning/前端页面/07-问答流程-问题解析.png)。  
> **流水线位置**：**问答流程诊断中枢·第一站：问题解析（Stage 1: Question Parsing & Intent Analysis）**。  
> **核心使命**：负责接收用户在智能问答中发起的口语化提问，结合多轮会话历史上下文，进行语言识别、意图分类、命名实体识别（NER）、代词指代消解与查询改写（Query Rewriting），输出结构化检索入参与过滤条件，为后续的向量化与路由检索奠定坚实基础。

### 三大组件职责划分：
1. **组件 1：原始问题 (Original Question Component)**：
   - 展现用户直接录入的原生口语提问，支持即席输入新问题发起实时解析测试；
   - 提取多轮问答历史上下文（会话轮次、上一轮追问与答案摘要），供排查“多轮代词指代消解错误”；
   - 提供上下文详情弹窗入口，调取长文本会话记忆。
2. **组件 2：结构化分析 (Structured Analysis Component)**：
   - 自然语言理解（NLU）抽取出的元属性：语言类别、用户意图、命名实体、时间约束与权限隔离；
   - 提供各属性单项一键复制；
   - 提取高频检索关键词药丸（Tag Pills），支持独立增删与单项重算。
3. **组件 3：规范化问题 (Normalized Question Component)**：
   - 代词补全后的“规范化完整问题”，支持行内单独编辑；
   - 用于多路召回的“查询改写词扩展包”，支持手动修正与大模型重算；
   - 自动推导出的元数据过滤条件（Filter Metadata）；
   - **两根高精度置信度进度条**（意图置信度 0.92、实体匹配度 0.88）；
   - 最终产出可在线编辑的结构化 JSON 视图。

## 五、端到端全业务闭环与调试场景

### 场景：多轮指代消解错误排查与重跑修复
1. **发现问题**：用户输入了简短的一句话：“如何安装它？”，模型在第 8 步给出了答非所问的结果；
2. **定位 Trace**：运维开发进入问答流程诊断，输入该问题的 Trace ID；
3. **查看组件 1（原始问题）**：看到上下文第 2 轮在讨论“产品问答助手”，说明原意里的“它”是指“产品问答助手”；
4. **查看组件 3（规范化问题）**：发现模型把“它”错误消解为了“企业网站”，导致后续召回全偏了；
5. **在线修正**：在组件 3 的输入框内，将规范化问题手动修正为：*“如何在企业网站中安装并配置产品问答助手？”*，意图修正为 *“安装指导”*；
6. **从此阶段重跑**：点击底部绿色大按钮 `[ ▶ 从此阶段重跑 ]`；
7. **链路验证**：后端自动带着修正后的参数重新跑 Stage 2~8，并在顶部生成新的衍生 Trace `QA-2025-0520-0086-R1`，最终生成精准佐证回答！
