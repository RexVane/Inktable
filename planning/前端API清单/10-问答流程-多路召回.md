# 10-问答流程-多路召回 前端 API 清单与交互契约

> **文档定位**：对应原型设计稿 [`10-问答流程-多路召回.png`](file:///d:/AIApp/Ordo/planning/前端页面/10-问答流程-多路召回.png)。  
> **流水线位置**：**问答流程诊断中枢·第四站：多路召回（Stage 4: Multi-channel Candidate Recall）**。  
> **核心使命**：负责接收 Stage 3 检索路由分配的通道预算与策略，并发向向量数据库（Dense Vector）、全文检索引擎（Sparse BM25）、知识图谱（Graph RAG）及结构化数据库发起候选片段检索，统计各通道召回耗时、初始相关性打分、权限过滤命中情况及重复候选数，为下一阶段的结果融合（Fusion）提供完整的候选集大盘。

## 二、本页面全部 API 契约总览表 (共 7 个 API)

| 序号 | 请求方式 | 接口路径 | 对应前端组件 / 触发时机 | 核心功能说明 |
|:---:|:---:|---|---|---|
| **1** | `GET` | `/api/v1/traces/:traceId/stages/recall` | 页面初始化 / 切换至此步骤 | **主数据源**：获取多路召回全量数据（4 大通道候选列表、前 5 项得分与权限状态、去重前总数 41、重复数 9、通道耗时分布） |
| **2** | `GET` | `/api/v1/traces/:traceId/pipeline` | 顶部 8 阶段步进条 | 获取各阶段耗时（问题解析 120ms、向量化 98ms、路由 35ms、召回 346ms 等）与状态 |
| **3** | `GET` | `/api/v1/traces/:traceId/stages/recall/chunks/:chunkId` | 点击任一候选文档 / 底部 `[ 📖 查看原文 ]` | **正文切片预览**：获取该切片的完整文本、所属文档来源、所属页码、Token 长度及命中高亮词 |
| **4** | `POST` | `/api/v1/traces/:traceId/stages/recall/filter` | 顶部工具栏 `TopK 20 ∨`、`仅当前版本`、`权限过滤` 切换 | **动态筛选重算**：即时按新配额或版本范围过滤各通道候选集并联动更新底部 4 项度量指标 |
| **5** | `POST` | `/api/v1/traces/:traceId/stages/recall/retry-channel` | 工具栏与底部 `[ ⟳ 重试失败通道 ]` 按钮 | **通道局部重试**：针对超时或异常通道（如网络抖动）单独发起重新检索，无需全局从头重跑 |
| **6** | `GET` | `/api/v1/traces/:traceId/stages/recall/channels/:channelId` | 点击各列底部 `[ 查看全部 N 条 ∨ ]` / `[ 查看详情 > ]` | **通道展开分页**：获取该通道完整召回切片列表（突破 Top 5 截断展示限制） |
| **7** | `GET` | `/api/v1/traces/:traceId/stages/recall/export` | 底部 `[ ⤓ 导出候选 ]` 按钮 | **全量数据导出**：将去重前 41 条多路召回结果导出为 JSON 或 CSV 调试报表 |

## 四、前端交互细节与异常状态设计

1. **已跳过通道的空态设计**：
   - 结构化查询通道因路由未命中而显示为灰度卡片，居中显示灰度空状态图标与「未触发结构化查询条件」文案，并提供「查看详情 >」按钮以供审计路由判定逻辑。
2. **多路并发超时与失败告警**：
   - 若某一路召回因外部服务异常（如 Neo4j 超时）失败，该列顶部显示红色告警徽标，并激活顶栏及底部的「重试失败通道」高亮可点击状态。
3. **点击行快速定位与高亮**：
   - 单击任意候选片段卡片时，触发选中高亮并解锁底部「查看原文」功能；双击直接弹窗渲染原切片 Markdown 预览。
4. **阶段推进导向**：
   - 点击右下角绿色主按钮 `[ 进入结果融合 ➔ ]`，系统记录当前检查态并路由平滑跳转至 Stage 5 (`11-问答流程-结果融合`)。
