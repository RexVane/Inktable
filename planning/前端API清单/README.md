## 💡 问答流程引擎的核心双重使命 (Dual-Role Architecture)

整个问答流程引擎（8 个阶段）在 Ordo 架构中承担 **两部分不可或缺的核心功能**：

1. **控制台网页内白盒诊断与沙箱推演 (Workbench Diagnostic & Testing Sandbox)**：
   - 供研发、算法与知识库管理员在控制台（Page 07 ~ 14）对任意问答链路（Trace）进行全透明的 8 阶段逐层拆解；
   - 支持实时检查分词 Token、查询向量分布、路由决策依据、召回候选去重、RRF 融合数学代入、Cross-Encoder 打分位移、Token 预算及流式输出；
   - 支持**动态调参、沙箱模拟运行（Simulate）、以及从任意阶段重放重跑（Trace Replay）**。
2. **真实业务应用中真实用户的实时生产请求流水线 (Production Execution Pipeline)**：
   - 供企业终端用户在【15-AI应用-智能问答】或嵌入企业网站的【16-智能助手 Widget】发起实时提问；
   - 底层引擎以低延迟全自动模式，串联执行 8 大阶段（问题解析 ➔ 问题向量化【默认开启单位 L2 归一化】 ➔ 检索路由 ➔ 多路召回 ➔ 结果融合 ➔ 重排 ➔ 提示词组装 ➔ GPT-5 流式生成）；
   - 自动沉淀 OpenTelemetry 追踪 Trace，并返回带有证据引用角标（如 `[1]`、`[2]`）的高置信度回答。
