# 04-知识库-数据解析 前端 API 清单与交互契约

> **文档定位**：对应原型设计稿 `04-知识库-数据解析.png`。  
> **流水线位置**：**第三站·核心算力加工厂**（`数据登记 ➔ 数据集 ➔ 数据解析 ➔ 构建知识索引 ➔ 知识库管理`）。  
> **核心使命**：负责把已登记并归入数据集的原始生文档（PDF、DOCX、PPTX、Excel、扫描件），在服务器后端调配多核 CPU/GPU 算力，进行文档检测路由、版面分析、OCR 提取、规则清洗，并规整转换为标准的 Markdown 文本与分块 JSON（Chunks），提供完全白盒化、透明可视、可抽检的解析工作台。

### 1.2 用户明确的核心业务规则

1. **顶部控制与 [ ⋮ ] 更多菜单**：
   - **知识库下拉框**：100% 复用已有 `GET /api/v1/knowledge-bases` 接口，切换时下方所有任务与预览数据联动切换；
   - **运行策略套餐 (Run Configuration)**：选择使用什么档位的算力去跑文档：
     - `默认解析运行`：智能自适应，文本走轻量快车道，遇到图片才调 OCR；
     - `深度 OCR 运行`：适合纯图片扫描件与纸质合同，强制逐页走 OCR 神经网络；
     - `纯文本快速运行`：适合原生规范 Markdown / TXT / Word，毫秒级纯文字提取；
   - **主控制大按钮**：`[ ▶ 开始解析 ]`（启动 Worker 并发处理）、`[ ⏸ 暂停 ]`（挂起调度）、`[ ⟳ 重试失败 ]`（针对 6 个失败任务一键重跑）；
   - **[ ⋮ ] 更多操作悬浮菜单（用户指定实装）**：
     - **`⚡ 自动化解析开关`**：已有队列自动执行解析，无需人工每次手动点开始；
     - **`⚙️ 并发线程设置`**：弹出专属配置弹窗，可自主调整 2 线程（节能轻载）、4 线程（推荐黄金标准）、8 线程（极速狂飙）；
     - **`📥 导出解析日志`**：将所有任务状态、耗时、引擎使用与报错信息导出为 `parsing_audit_log.json`；
     - **`🧹 清空待处理队列`**：二次确认后清空排队中的任务，不影响正在运行中的任务。
2. **左栏任务队列三大分类口径（消除歧义）**：
   - **`⟳ 处理中 (38)`**：CPU/GPU 正在进行解析运算的进行中文档；
   - **`⏳ 排队中 (160)`**：刚从数据登记接入、尚未轮到调度、正在队列中等待的文件（严禁与错误混淆）；
   - **`🔴 解析失败 (6)`**：解析出错（如文件格式损坏、带密码加密打不开、超时等）的文件，支持针对性排查与一键重试。
3. **中栏万能文件查看器机制**：
   - **双轨对照底稿机制**：画布中间渲染的是**「解析前的原版文件」**，上面**叠加上后端解析出来的彩色识别框线**；
   - **底部 4 大图例（Legend）透明可追溯**：
     - 🟩 `pypdf`：代表直接提取的原生纯文本段落；
     - 🟦 `MinerU`：代表识别出的多栏排版、大标题与表格；
     - 🟧 `OCR`：代表从插图或扫描图片中抠出来的文字；
     - 🟪 `VLM`：代表视觉大模型理解总结的复杂图表。
4. **右栏一体化大卡片大框（用户拍板实装）**：
   - 右栏统一整合为单一高阶白底大卡片，外框与左中两栏水平对齐；
   - 上部为当前具体某一页（如第 45 页）的质量打分、耗时、所用引擎与修复告警；
   - 下部通过分割腰线内嵌【内容对比】，左右对照展示规则清洗前后的纯文本差异，绿色高亮标出清洗动作。
5. **后端算力与吞吐量本质**：
   - 解析、OCR、清洗与切块 100% 在后端 Worker 运行，前端为纯可视化指挥台；
   - 底部吞吐量 `128 页/分钟` 代表每秒处理 2.1 页，波浪折线表达近几分钟内的吞吐波动走势。

## 二、页面全生命周期接口总览表 (17 个 API)

| 序号 | 接口路径 | 请求方式 | 对应前端组件 / 触发时机 | 核心功能说明 |
|:---:|---|:---:|---|---|
| **1** | `/api/v1/knowledge-bases` | `GET` | 顶栏【知识库】选择器 | **复用接口**：获取当前工作空间下已有的知识库下拉列表 |
| **2** | `/api/v1/parsing/profiles` | `GET` | 顶栏【运行】策略套餐选择器 | 获取系统支持的解析模式（默认混合、深度OCR、极速纯文本） |
| **3** | `/api/v1/parsing/start` | `POST` | 顶栏 `[▶ 开始解析]` 按钮 | 启动当前知识库排队队列的后台并发解析流水线 |
| **4** | `/api/v1/parsing/pause` | `POST` | 顶栏 `[⏸ 暂停]` 按钮 | 临时挂起当前后台 Worker 任务队列调度 |
| **5** | `/api/v1/parsing/resume` | `POST` | 顶栏继续调度 | 恢复被暂停的解析任务继续向下流转 |
| **6** | `/api/v1/parsing/retry-failed` | `POST` | 顶栏 `[⟳ 重试失败]` 按钮 | 将当前状态为失败的 6 个任务重新置入排队中 |
| **7** | `/api/v1/parsing/pipeline-stats` | `GET` | 中间四阶段流水线进度卡片 | 获取检测路由、解析、清理、Markdown/JSON 四步累计处理总数 |
| **8** | `/api/v1/parsing/tasks` | `GET` | 左栏【任务队列】 | 获取任务列表，按处理中、排队中、解析失败分组与分页 |
| **9** | `/api/v1/parsing/tasks/clear-pending` | `POST` | `[⋮]` 菜单【清空待处理队列】 | 一键清空排队中（160项）任务，保留运行中任务 |
| **10** | `/api/v1/parsing/settings` | `GET` | 页面初始化 / 并发弹窗回显 | 获取当前后台并发 Worker 线程数与自动化解析开关状态 |
| **11** | `/api/v1/parsing/settings` | `PATCH` | `[⋮]` 自动化开关 / 并发设置弹窗 | 更新自动化解析开关 (`autoParsingEnabled`) 与并发线程数 (2/4/8) |
| **12** | `/api/v1/parsing/logs/export` | `GET` | `[⋮]` 菜单【导出解析日志】 | 打包导出包含任务明细与系统硬件指标的审计日志文件 |
| **13** | `/api/v1/documents/:id/preview/pages` | `GET` | 中栏左侧【页面缩略图条】 | 获取当前选中文档所有页面的缩略图 URL、页码与宽高比例 |
| **14** | `/api/v1/documents/:id/pages/:pageNum` | `GET` | 中栏右侧【主画布】 | 获取当前页高保真渲染原版图片与版面元素彩色识别框 (BBoxes) |
| **15** | `/api/v1/documents/:id/pages/:pageNum/inspect` | `GET` | 右栏上方【页面信息】卡片 | 获取当前页的路由依据、调用引擎、文字层质量打分、耗时与告警 |
| **16** | `/api/v1/documents/:id/pages/:pageNum/diff` | `GET` | 右栏下方【内容对比】卡片 | 获取当前页清洗前原文 vs 清洗后纯文本，以及高亮差异位置 |
| **17** | `/api/v1/system/resources` | `GET` | 底部通栏【运行资源与吞吐监控】 | 实时获取本机 CPU、GPU 占用、队列长度与吞吐量历史波浪折线点 |
