# 11-问答流程-结果融合 前端 API 清单与交互契约

> **文档定位**：对应原型设计稿 [`11-问答流程-结果融合.png`](file:///d:/AIApp/Ordo/planning/前端页面/11-问答流程-结果融合.png)。  
> **流水线位置**：**问答流程诊断中枢·第五站：结果融合（Stage 5: Multi-Source Fusion & RRF Ranking）**。  
> **核心使命**：负责接收 Stage 4 多路并发召回的候选文档切片集合（向量召回 15 条、全文召回 17 条、图谱召回 9 条，原始候选共 41 条），通过内容指纹去重（32 条）、权限二次复核（过滤 0 条）、Min-Max 分数归一化，并运用倒数排名融合算法（Reciprocal Rank Fusion, RRF）多维加权计算，输出前 20 条最优质的融合候选集，并呈现透明的分数计算推演过程。

## 二、本页面全部 API 契约总览表 (共 10 个 API)

| 序号 | 请求方式 | 接口路径 | 对应前端组件 / 触发时机 | 核心功能说明 |
|:---:|:---:|---|---|---|
| **1** | `GET` | `/api/v1/traces/:traceId/stages/fusion` | 页面初次加载 / 切换至此步骤 | **主数据源**：获取结果融合全景数据（三路原始召回摘要、4大度量卡片、Top 20 融合候选集、底层分数与去重明细表） |
| **2** | `GET` | `/api/v1/traces/:traceId/pipeline` | 顶部 8 阶段步进条 | 获取流水线各步骤耗时与执行状态 |
| **3** | `PUT` | `/api/v1/traces/:traceId/stages/fusion/weights` | 操作组 `[ 🎛️ 调整权重 ]` 弹窗保存 | **融合调优**：动态修改融合算法（RRF / 加权线性融合 / 分数插值）及各通道权重比例，即时预览重排效果 |
| **4** | `POST` | `/api/v1/traces/:traceId/stages/fusion/reset-weights` | `[ 🎛️ 调整权重 ]` 弹窗中 `[ 恢复默认 ]` 按钮 | **重置权重**：一键恢复系统推荐基准权重（RRF k=60，向量 0.45，全文 0.35，图谱 0.15，Top-20） |
| **5** | `GET` | `/api/v1/traces/:traceId/stages/fusion/calculation/:candidateId` | 选中明细行后点击 `[ 📄 查看计算 ]` | **公式数学推演**：查看该候选切片在 RRF 算法下的公式拆解、排名倒数代入过程与最终加权推导明细 |
| **6** | `GET` | `/api/v1/traces/:traceId/stages/fusion/candidates` | 右翼点击 `[ 查看全部 20 条 ∨ ]` | **融合候选全量展开**：分页获取全部 20 条已融合候选切片完整摘要及多通道来源徽标 |
| **7** | `GET` | `/api/v1/traces/:traceId/stages/fusion/chunks/:candidateId` | 点击任一候选行 / 查看切片原文 | **候选切片正文预览**：获取该融合切片的正文分块、元数据、所属文档名、页码及 ACL 权限校验结果 |
| **8** | `GET` | `/api/v1/traces/:traceId/stages/fusion/logs` | 开发者排障 / 抽屉日志 | 获取切片哈希去重耗时、ACL 权限校验列表及分数平滑归一化日志 |
| **9** | `GET` | `/api/v1/traces/:traceId/stages/fusion/export` | 导出融合报表功能 | **数据导出**：将全量融合结果、原始排名、归一化分数与去重组导出为 JSON 或 CSV 分析文件 |
| **10** | `POST` | `/api/v1/traces/:traceId/stages/fusion/rerun` | 权重调整后点击「立即重算后续阶段」 | **阶段重跑**：锁定修改后的融合参数，从融合阶段向下级联重算重排、提示词与回答生成，生成新衍生 Trace |

## 四、前端交互行为规范与核心校准法则

1. **五层严格数学校准法则（Mathematical Calibration Contract）**：
   - **输入层**：向量召回 (15) + 全文召回 (17) + 图谱召回 (9) = **原始候选数 41**。
   - **去重层**：跨通道识别 9 篇内容重叠切片，`41 - 9` = **去重后候选数 32**。
   - **权限层**：ACL 安全策略核验移除 0 篇，**合规保留 32 篇**。
   - **融合层**：RRF 加权打分排序，按 Top 20 截断 = **融合候选数 20**。
   - **明细映射**：底部明细表前 5 行与右翼「融合候选集」Top 5 候选的文档标题、原始分、归一化分与融合分 100% 严格一致。

2. **路由流转与 API 调用的明确分界（关于「进入重排 >」按钮）**：
   > [!IMPORTANT]
   > 页面右侧操作组的 **`[ 进入重排 > ]`** 按钮为 **SPA 客户端路由流转行为**（执行 `window.go('qaflow/rerank')`）。
   > - **无参数修改时**：直接执行路由切换，到达重排页面后自动调取 `GET /api/v1/traces/:id/stages/rerank`；
   > - **有算法参数修改时**：前端在弹出保存确认后先调用 `POST /api/v1/traces/:id/stages/fusion/rerun` 固化新链路，再自动无缝跳转至新 Trace 的重排阶段。

3. **来源渠道彩色徽标规范**：
   - 融合列表中清晰标注文档来源于哪些通道：`[向量]`（绿色，#16a34a）、`[全文]`（蓝色，#2563eb）、`[图谱]`（紫色，#9333ea）。多个来源同时命中时横向排列展示。

4. **公式可视化浮层**：
   - 当点击任一行并点击 `[ 查看计算 ]` 时，以 LaTeX 数学公式形式直观呈现 `RRF Score` 的分子、分母与权重求和过程，帮助算法工程师即时定位排序异常原因。
