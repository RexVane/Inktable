# 12-问答流程-重排 前端 API 清单与交互契约

> **文档定位**：对应原型设计稿 [`12-问答流程-重排.png`](file:///d:/AIApp/Ordo/planning/前端页面/12-问答流程-重排.png)。  
> **流水线位置**：**问答流程诊断中枢·第六站：重排（Stage 6: Cross-Encoder Reranking & Precision Pruning）**。  
> **核心使命**：负责接收 Stage 5 粗排融合输出的 20 个候选切片，调度专业 Cross-Encoder 语义深度交叉比对模型（如 `bge-reranker-v2-m3`），对输入问题与候选正文进行全注意力交叉打分，将相关性打分从单向向量近似修正为精细语义匹配度，并依据保留阈值（`score >= 0.75`）将候选集从 20 精简至 8 个黄金切片，避免无用上下文干扰后续大语言模型生成。

## 二、本页面全部 API 契约总览表 (共 6 个 API)

| 序号 | 请求方式 | 接口路径 | 对应前端组件 / 触发时机 | 核心功能说明 |
|:---:|:---:|---|---|---|
| **1** | `GET` | `/api/v1/traces/:traceId/stages/rerank` | 页面初次加载 / 切换至此步骤 | **主数据源**：获取重排全景（模型状态卡、重排前候选 20 与位移升降徽标、重排后保留 8 项得分、折线图打分分布、首项切片详情） |
| **2** | `GET` | `/api/v1/traces/:traceId/pipeline` | 顶部 8 阶段步进条 | 获取 8 阶段耗时（重排耗时 512ms）与流水线流转状态 |
| **3** | `GET` | `/api/v1/traces/:traceId/stages/rerank/chunks/:chunkId` | 点击任一候选文档卡片 | **右侧切片深度审视**：拉取该切片的完整正文、重排前后分数位移（0.792➔0.912）、Cross-Encoder 推理语义判定词、Token 消耗及权限 |
| **4** | `PUT` | `/api/v1/traces/:traceId/stages/rerank/config` | 底部 `[ 🔄 更换模型 ]` / `[ 📐 调整阈值 ]` 弹窗保存 | **重排超参微调**：切换 Cross-Encoder 模型（bge/cohere/gte）、修改保留分数阈值（如从 0.75 改为 0.80）或最大保留 Top-K（如 8 改为 5） |
| **5** | `POST` | `/api/v1/traces/:traceId/stages/rerank/compare` | 底部 `[ 📊 对比结果 ]` 按钮 | **重排收益评估**：对比重排前后 NDCG@10、相关性提权增益比率与淘汰切片原因汇总 |
| **6** | `GET` | `/api/v1/traces/:traceId/stages/rerank/logs` | 开发者排障与性能监控 | 获取 Reranker 批量推理批次大小（Batch Size）、显存/内存占用及逐条打分耗时审计 |

## 四、前端交互与动态状态机行为

1. **重排位移徽标颜色规范**：
   - 排名上升：绿色浅底绿字徽标，如 `↑ 5`、`↑ 1`、`↑ 2`；
   - 排名下降：橙红浅底红字徽标，如 `↓ 3`；
   - 排名未变：显示减号灰色中线 `-`；
   - 阈值淘汰：灰色胶囊徽标显示 `淘汰`。
2. **两栏点击联动抽屉**：
   - 无论点击「重排前」列表或「重排后」列表中的任一卡片，右侧「文档详情」抽屉立即平滑滑入，显示该切片完整正文、相关度变化箭头（如 `0.792 ➔ 0.912`）、Cross-Encoder 模型语义推理分析及权限校验绿标。
3. **折线图阈值拖拽联动**：
   - 折线图中的「保留阈值 0.75」虚线支持直接鼠标拖拽调整，释放后触发重新打分阈值计算，左侧与中间候选列表动态重新划定保留与淘汰。
4. **阶段流转**：
