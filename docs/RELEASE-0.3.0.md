# Inktable 0.3.0 发布说明

**日期**：2026-08-13
**定位**：体验重构版。0.2.0 打通了「能查、能问、能回溯」的知识管线，
0.3.0 按真实使用反馈重做了信息架构与设置体系，并补上了两个此前
"有代码但没用上"的缺口：存量向量补齐与浏览器下载来源。

## 布局重构（v3 信息架构）

- **左栏只放导航**：范围（全部文件/重复内容）+ 文件树。分类、类型、
  文件书三组按用户反馈撤下（数据与右键归类保留，可随时恢复）。
- **文件树**（`GET /files/tree`）：树根 = 已启用来源，逐层展开真实目录，
  完全从库内登记路径推导、不扫磁盘；点目录名中栏递归列出该目录文件
  （`/files?dir=` 前缀过滤），点箭头只展开收起；展开状态持久化。
  图标为 SVG 矢量（文件夹/旋转箭头/文档），替换字符三角。
- **中栏两页切换**：列表页（搜索框 + 文件列表）⇄ 详情页（全文阅读 +
  「‹ 返回」，Esc 也可返回）。问答引用点开同样落到详情页。
- **列表按扩展名分组**（`/files?group=ext`）：同类型聚在一起、大组靠前、
  组内最新在上；排序在服务端做（窗口函数），分页跨页不断组；
  组头粘性置顶。搜索结果保持按相关度。
- 搜索框修复双层焦点环（全局 focus-visible 与容器 focus-within 叠加），
  提示语改为「搜索文件内容或文件名…」。

## 文件查看器

- `GET /files/{id}/content`：按 ordinal 分页返回全部子层分片，不截断正文；
  详情页滚动到底自动续载，读完显示「全文完 · 共 N 段」。
- 详情头部新增「用默认应用打开」（`shell.openPath`）与「在 Finder 中显示」；
  无法解析正文的格式明确提示并引导用默认应用打开。

## 可见性口径：停用来源即从视图消失

- 统一口径 `VISIBLE_FILES_COND`：停用来源的文件**保留记录与索引**，
  但从文件列表、统计、导航、全文搜索、分类计数中全部隐藏；
  重新启用即恢复，无需重扫。孤儿文件（来源已移除）始终可见。
- 重复内容判定同步收口：对端副本也必须可见才算重复。
- **磁盘上已消失的文件同样隐藏**（同日追加）——除非有保全副本
  （内容仍可读，正是保全功能的价值）；文件回到原位后重扫自动恢复可见。

## 默认自动分类

- `POST /classify/auto_ext`：把未分类且未经用户确认的文件按扩展名归入
  「按扩展名」分类树，并为每个扩展名补一条低优先级规则（新文件自动归类）。
  绝不覆盖用户手动归类。启动、来源变更、新文件入库后自动触发；
  设置 → 通用配置可关闭。

## 嵌入模型换代：Ollama bge-m3

- 内置的 model2vec 静态嵌入（potion-multilingual-128M 裁剪版，256 维，
  查表加权平均）整体移除：静态嵌入对否定、语序、上下文不敏感，是检索
  质量的天花板。
- 换为本机 **Ollama + bge-m3**（1024 维上下文编码，多语言，8192 上下文）：
  `GET /api/tags` 探测（30 秒缓存）、`POST /api/embed` 批量编码、
  统一 L2 归一化。未检测到 Ollama 或未拉模型时全链路自动降级纯关键词
  检索，功能不塌；设置 → 模型配置有状态卡与安装指引。
- **维度迁移自动化**：启动时检测 `chunks_vec` 表维度与当前模型不符即
  重建表并清空 `embedding_model_id`，由既有回填路径分批重嵌全库。
- 打包收益：sidecar 不再捆绑模型权重与 tokenizers/safetensors 原生库，
  仓库删除约 770 MB 模型文件。
- 环境变量 `INKTABLE_OLLAMA_URL` 可指向非默认 Ollama 地址。

## 语义向量补齐（关键修复）

- 发现真实库 3627 个分片仅 194 个（5%）有向量——大部分内容在嵌入模型
  就位前以纯 FTS 模式索引，且此前**没有补课路径**，语义检索长期只覆盖
  12 个文档。
- 新增 `POST /index/embed_backfill`：幂等分批补齐活跃索引版本中
  `embedding_model_id IS NULL` 的分片；前端在解析队列排空后自动驱动。
- 实测：重启一次后 3627/3627 全部向量化，161 个已解析文档全量进入语义检索。

## 设置重构（三栏）

- **通用配置**：界面缩放（webFrame 90%–125%）、外观（跟随系统/浅色/深色，
  nativeTheme）、自动归类开关、数据位置。
- **文件来源**：原来源管理列表；「添加目录/重新发现」归属此页。
- **模型配置**：AI 问答接口表单 + 本地向量模型状态卡（读 `/health`）。
- **数据位置可迁移**：选择新目录后自动完成 停服务 → 整体搬迁（数据库/
  备份/保全副本，跨卷回退为复制校验删除）→ 记录配置 → 以
  `INKTABLE_DATA_DIR` 重启 sidecar → `POST /system/rebase_preserved`
  重写库内保全副本路径前缀。

## cc-switch 导入与真实连接检测

- `GET /integrations/ccswitch`：只读解析 `~/.cc-switch/cc-switch.db`，
  把 codex（OPENAI_API_KEY + TOML base_url/model）与 claude
  （ANTHROPIC_BASE_URL/AUTH_TOKEN/模型 env）配置转换为
  OpenAI 兼容三元组，endpoint 统一规范化为 `…/v1`；同端点同密钥去重。
- 模型配置页按来源应用分组展示（Codex / Claude Code 中转 / Claude 桌面端），
  当前供应商置顶标注；点选填入表单并蓝底高亮，重开时自动标出与当前
  配置一致的一项。
- **检测连接 = 真实补全测试**：发真实指令并要求返回文本，成功显示
  实际回复与耗时（如「连接正常 · 1.2s 实际回复『确认』」）；
  max_tokens 给足 512，避免推理型模型烧完预算造成"连通但空响应"假阴性；
  接口通但无有效文本时明确提示检查模型名或中转协议兼容性——
  正好用于甄别 Anthropic 中转是否兼容 OpenAI 协议。

## 来源发现扩展

- **QQ NT（新版 QQ）**：`…/QQ/nt_qq_<hash>/nt_data/File` 接收目录；
  作为明确收件位置，**目录存在即显示**（标注"暂无文档"），
  启用后来件自动收录。旧版路径保留。
- **办公应用**：飞书 / Lark / 钉钉 / 企业微信的接收目录探测规则
  （容器与直装路径），装了应用且有文档才出现。
- **浏览器**：默认下载位置（~/Downloads）统一归「下载」系统来源，
  不再挂误导性的"Chrome 下载"名；只有自定义下载目录才单独列出，
  并带真实文件统计。覆盖 Chrome / Edge / Brave / Arc / Vivaldi /
  Safari / Firefox（prefs.js）。
- 「重新发现」不再按"有无文档"过滤——噪音抑制移到发现阶段，
  下载、QQ 这类明确入口即使为空也可先启用。

## 问答体验（同日追加）

- **意图路由**：模型先判断问题是否需要本地资料——寒暄/常识/写作等通用
  问题直接自然回答（界面标注「通用回答 · 未引用文件库」，来源可辨），
  文件相关问题仍走全部硬校验；检索为空也不再直接拒答。
- **多轮对话浓缩**：前端携带最近 4 轮问答，追问（"那第二个呢？"）先被
  轻量改写成独立完整问题再检索，生成仍用用户原话；首问零额外开销
  （`validation.condensed_query` 留痕）。
- **拒答自动重试**：模型答"资料不足"时自动换更贴近文档原文的关键词
  重检索一次（有界一轮，`validation.retrieval_retry` 留痕）。
- **句级自动归因**：模型不写 [Cn] 时逐句与证据做重叠归因（句中数字必须
  在证据中出现），全部落到证据上才接受并自动注引用；否则仍走降级。
- **真实连接检测 + 启动自动检测**：检测连接改为真实补全（显示实际回复与
  耗时）；应用启动与服务恢复后自动后台检测，右上角直接给出可用结论。
- 模型调用失败降级为检索片段并说明原因，不再报 5xx。

## 检索性能（bge-m3 换代后的修复）

- **重排复用库内向量**：换 bge-m3 后重排阶段现场编码 80 个候选要
  6–14 秒（旧静态模型毫秒级，从未暴露）。改为直接批量读取
  `chunks_vec` 已入库向量，只对尚未回填的新片现场编码；查询变体
  合并为一次批量编码。实测真实库：单查询 13.9s → 0.4s、8.1s → 2.0s
  （重排 13.7s → 0.2s）。72 题评测复测达标（Recall@5 95.0%）。
- **生成超时放宽**：长上下文 + 详尽回答在中转服务上经常超过 60 秒，
  问答生成超时放宽到 180 秒，"模型服务响应超时" 大幅减少。

## 引用与提示词（同日追加）

- **三位数引用标签修复**：证据预算加大后标签可达 `[C100+]`，前后端

  统一改为支持三位，带回归测试。
- **正文角标重做**：连续 `[C8][C9]` 合并为一组小圆号（只显示数字），

  角标同款圆徽；旧会话存档恢复时自动洗成新样式。
- **系统提示词扩充**：先结论后细节、对比信息用表格、避免"资料还
  记载"式逐条复述腔、资料冲突并列说明、按提问语言作答。

## 已知限制

- ONNX Cross-Encoder 已实装并冻结评测。**+15% 相对门槛已于 2026-08-19 废止**
  （高基线下等价于要求 nDCG 绝对值 97%，数学上失真），改为绝对多目标口径。
  按新口径在**真实库**复测 `cascade`：R@5 94.3%（门槛 95%）、

  搜索 P95 3537ms（门槛 2500ms）—— 四条门槛过一条都不算，因此仍不切生产默认。
